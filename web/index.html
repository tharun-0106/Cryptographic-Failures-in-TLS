Stage 2a: CBC Padding-Oracle Attack

Demonstrates the vulnerability in TLS MAC-then-encrypt CBC mode (Vaudenay 2002 / POODLE CVE-2014-3566 / Lucky13). An active chosen-ciphertext attacker recovers plaintext bytes by observing only 1 bit of feedback: whether the PKCS#7 padding was valid.

Adversary: Active, chosen-ciphertext attacker with no knowledge of the AES key.
Mechanism: Submits forged ciphertexts with adjusted tail bytes. When valid PKCS#7 padding is detected, the intermediate decrypt value is revealed via XOR.
Real-World Incidents: POODLE (CVE-2014-3566), Lucky13 (CVE-2013-0169), Zombie POODLE.

🛡️ Countermeasure: AEAD (AES-GCM mandated in TLS 1.3)

In TLS 1.3, MAC-then-encrypt CBC mode is removed. AES-GCM verifies the 16-byte authentication tag before any decryption or padding inspection occurs:

255 Tampered records tested
0 Accepted (All rejected via InvalidTag)

No padding, no oracle: zero information leaked on decryption failure.

Stage 2b: RC4 Keystream Bias Attack

RC4 is a stream cipher historically used in TLS. Its key scheduling algorithm (KSA) does not generate a perfectly uniform keystream. The second output byte Z2 has a strong bias towards 0 with probability P(Z2 = 0) ≈ 2⁄256 = 0.781%, double the ideal 1⁄256 = 0.391%.

Adversary: Passive eavesdropper collecting ciphertexts across N sessions of the same repeated secret (e.g. session cookie).
Vulnerability: Mantin-Shamir bias (2001) and AlFardan et al. (2013). Plaintext P2 = C2 ⊕ Z2. When Z2 = 0, C2 = P2.
Real-World Incident: RC4 NOMORE attack (2015). RC4 banned entirely in TLS by RFC 7465.

🛡️ Countermeasure: RFC 7465 RC4 Ban

RFC 7465 prohibits negotiation of RC4 cipher suites in all versions of TLS. Modern ciphers like AES-GCM and ChaCha20-Poly1305 have pseudo-random keystreams indistinguishable from true randomness, eliminating all keystream bias attacks.

Stage 2c: Weak / Export Diffie-Hellman (Logjam-Class)

Demonstrates the Logjam attack (CVE-2015-4000). When a server supports export-grade or weak DH primes (e.g. 512-bit historically, or simulated smaller primes for classroom demonstration), an eavesdropper recording public values (p, g, A, B) can solve the Discrete Logarithm Problem using the Baby-Step Giant-Step (BSGS) algorithm and recover the shared AES session key.

Adversary: Passive network eavesdropper recording traffic in cleartext.
Math: Given A = ga mod p, Eve solves for private exponent a in O(√p) operations. Real Logjam used Number Field Sieve (NFS) with precomputed primes.
Critical Insight: The attacker breaks the key exchange; AES itself is never attacked directly!

🛡️ Countermeasure: Mandate Strong DH Groups & ECDHE

TLS 1.3 completely removes export DH and weak cipher suites. It mandates predefined named groups (e.g. X25519, secp256r1, or DH ≥ 2048-bit). For 2048-bit primes, solving discrete log requires months of supercomputer precomputation per prime, rendering live attacks computationally infeasible.

Stage 2d: Loss of Forward Secrecy & Retroactive Decryption

Evaluates what happens when an attacker passively records encrypted network traffic today, and the server's long-term RSA private key is stolen, leaked, or subpoenaed months or years later (as occurred in the Heartbleed vulnerability).

Static RSA Key Exchange: Client encrypts pre-master secret using server's long-term RSA public key. If the private key is ever compromised, ALL past recorded sessions can be decrypted retroactively.
Ephemeral (EC)DHE: Fresh keypairs are generated per session and wiped from memory after the handshake. A subsequent leak of the long-term identity key cannot decrypt past traffic.

🛡️ Countermeasure: TLS 1.3 Ephemeral Key Exchange

TLS 1.3 completely removes static RSA key transport. Ephemeral (EC)DHE is mandatory for every session. Forward secrecy is guaranteed by default, ensuring historical communications cannot be decrypted even if private keys are compromised.
